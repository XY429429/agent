# RAG 实践要点

## 切块与检索

RAG 的第一步不是模型，而是切块。切块要保证语义完整：按标题和段落切，块间保留少量重叠。中文检索可以用字 + 二元组做 TF-IDF 基线，成本低、可解释；数据量上来后换成 embedding 向量库，召回和语义匹配会更好。

## 引用与可追溯

每个检索结果都要带 doc_id、标题、分数和原文片段。生成答案时要求模型在句末标注引用；汇总时去重，但不能丢掉来源。验收时检查引用数量、覆盖率和是否存在编造引用。没有引用的结论要标记为“未验证”。

## 质量评估

RAG 评估至少看三件事：召回是否包含正确答案、答案是否只基于检索内容、引用是否准确。离线可以用固定问题集做回归；线上要记录 query、命中 doc_id、最终答案和用户反馈，形成闭环。

## 常见失败

检索不到时不要让模型硬编；应返回“资料不足”，并让主管生成补充检索任务。检索结果太长会挤爆上下文，要先截断再重排。不同文档冲突时，汇总 agent 要显式列出冲突，而不是悄悄选一个。

## 与多 agent 协作

员工 agent 各自检索自己负责的子问题，避免一个 agent 读全部资料。汇总 agent 负责合并重复内容、对齐术语、保留引用。主管 agent 只检查结论和验收标准，不重复读原文。这样既降低 token，又让每个角色的职责清晰。
